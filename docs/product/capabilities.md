# 핵심 역량과 적용 영역

## 핵심 기능

| 역량 | 제공 구조 | 문서화할 때의 조건 |
|---|---|---|
| 다중 프로토콜 | TCP / HTTP / WebSocket 및 TLS 계층 | 외부 REST API 계약과 내부 LAMP 프레이밍은 구분 |
| Chain Routing | URI 기반 단계별 서비스 포워딩 | 체인 및 Hook의 책임 범위를 정의 |
| Plugin 실행 | 공유 라이브러리 로딩과 트랜잭션 진입점 | Plugin ABI 버전 호환 필요 |
| Plugin Reload | 수동 재적용 및 설정 기반 파일 감시 | 자동 감시는 기본값이 아님 |
| 운영 계층 | Master / Node / Server 및 관리 인터페이스 | 관리 계층의 HA를 별도 검증 |
| 관측성 | 메트릭·추적·구조화 로그 관련 구현 | 실제 외부 모니터링 통합 확인 필요 |
| 배포 | 자체 오케스트레이션 / Kubernetes 연계 | 두 모드의 프로세스 관리 주체 다름 |

## 대표적인 적용 시나리오

**실시간 금융 게이트웨이** — 외부 채널과 업무 서비스를 분리하고 트랜잭션 처리를 공통 방식으로 연결합니다. 개별 고객 요구 구현은 별도 프로젝트의 범위입니다.

**실시간 데이터·이벤트 처리** — 다중 연결 및 이벤트 배포가 필요한 서비스를 독립 모듈로 구성할 수 있습니다. 최대 fan-out, 처리량 등 수치는 구체적인 환경에서 실측해야 합니다.

**API·레거시 연계** — 중간 서비스에 인증·변환·캐시와 같은 관심사를 배치할 수 있습니다. 외부 표준 API는 별도 Gateway 계약이 필요할 수 있습니다.

## 피해야 할 표현
